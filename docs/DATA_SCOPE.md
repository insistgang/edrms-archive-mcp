# 数据范围与筛选确认表（待客户/鸿翼签认）

来源是项目沟通中对“目录、ZIP、表格、系统日志、本地副本、季度筛选”的讨论；这里只保留技术结论，不保存录音原文及商务内容。未签认不视为新增开发承诺。

## 数据范围

| 数据对象 | 首期建议 | 接口/身份 | 必须确认 |
|---|---|---|---|
| 案卷/文件目录和字段 | 纳入 | 原生检索与详情，真实用户 | 四门类ID、字段英文键、中文含义、类型、敏感级别 |
| 文件—原文关联与正文 | 纳入可用样本 | 关联列表、版本下载、逐层权限 | 原文类型/大小/版本、读取与下载权限 |
| Excel业务表格 | 作为原文纳入 | 保留sheet/row/cellRange | 公式缓存、日期样式、隐藏表、合并单元格与校验口径 |
| 网站列表中的业务字段 | 在档案范围内纳入 | 优先原生JSON，不抓HTML | 是否已在详情接口、是否可授权展示 |
| 系统日志/用户账号/权限规则 | 不默认纳入问答 | 单独管理域 | 业务目的、法律/安全批准、访问角色、脱敏、留存，不把管理员可见当作允许建库 |
| 图片/扫描页 | 组件确认后 | 获批OCR | 引擎/接口、置信度、页位置、人工复核与资源限制 |
| 本地导出副本 | 仅人工验证/备份 | 授权导出，不自动供模型 | 更新/删除/权限撤销同步；不默认共享，不代替原系统 |

## 结构化时间筛选

工具新增filters契约，**目前Mock可执行，LIVE显式拒绝**，待原生接口字段和语法实测后启用。不能下载一页后再过滤冒充完整日期查询。

```json
{
  "query": "检查通知",
  "archiveTypeId": "<确认后的门类ID>",
  "filters": {
    "yearFrom": 2026,
    "yearTo": 2026,
    "dateField": "formedDate",
    "dateFrom": "2026-01-01",
    "dateTo": "2026-03-31"
  },
  "pageIndex": 1,
  "pageSize": 10
}
```

- 日期端点包含；严格YYYY-MM-DD；未知条件、倒置范围、非法日期拒绝。
- formedDate表示形成日期，filingDate表示归档日期；两者不混用，字段映射尚未实机确认。
- “近一个季度”须澄清是最近三个月、当前季度至今还是上一完整自然季度，并明确时区/基准日期。当前程序不自动猜测。
- 年度字段不一定等于形成日期年份；同时给年度和日期时按AND处理。
- 缺少所筛选日期的Mock记录不命中；生产缺值策略待业务确认。
- 原生筛选启用前验证跨门类、分页总数、排序、权限、空值及日期边界；不把LLM后过滤当作上游授权过滤。
